# AGENTS.md — правила для агентов в репозитории SkillWharf

Документ описывает, как вести работы в этом репозитории. Он применяется к
любому агенту (infra/devops, backend, frontend, docs), который выполняет
задачи по проекту.

## 1. Контекст проекта

| Параметр | Значение |
|---|---|
| Репозиторий | `C:\Projects\AI\ai-skillwharf` |
| Remote | `https://github.com/iilmchat/ai-skillwharf.git`, ветка `main` |
| Стек | TypeScript, NestJS, pnpm workspaces |
| Пакеты | `apps/*`, `packages/*` (см. `pnpm-workspace.yaml`) |
| Пакетный менеджер | pnpm, версия из `packageManager` (12.18.0) |
| Документация | `docs/01-architecture`, `02-ecosystem`, `03-billing`, `04-security`, `05-operations`, `openapi` |
| CI | `.github/workflows/ci.yml`, job `lint-docs` |

Что уже настроено:

- `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `.gitignore`;
- `markdownlint-cli2` + `.markdownlint.json` (MD013/MD033/MD041 выключены);
- скрипт `pnpm run lint:docs` (`markdownlint-cli2 "docs/**/*.md"`);
- CI: Node 22, `pnpm install --frozen-lockfile`, линт Markdown.

## 2. Жёсткие правила

1. **Только этот репозиторий.** В `C:\Projects\AI` много других проектов —
   не читай и не меняй их без прямого указания.
2. **Чужие незакоммиченные изменения неприкосновенны.** Перед `checkout`,
   `reset`, `clean`, `stash` смотри `git status`. Запрещены `push --force`,
   `reset --hard` и удаление веток без письменного разрешения.
3. **Секреты — только в файлах.** Не печатай содержимое `.env`, токенов и
   ключей, не коммить их. Нужен токен — попроси файл и читай программно,
   в выводе показывай статусы и длины, а не значения.
4. **Минимальный диф.** Никаких зависимостей, файлов и настроек «на будущее».
   Каждое расширение объёма — отдельный вопрос.
5. **Проверка обязательна.** Задача закрыта только после локальной проверки
   и зелёного CI.
6. **Не выдумывай инфраструктуру.** Хоста, домена и прод-окружения у проекта
   пока нет; для деплоя сначала нужно решение владельца.

## 3. Рабочий цикл

1. **Осмотр.** Прочитай задачу и факты: `git status`, `git log -3`, структура
   каталогов, затронутые файлы.
2. **План.** Коротко перечисли шаги и риски; при выборе инструмента или
   структуры предложи вариант и обоснуй.
3. **Реализация.** Правь файлы инструментами, а не heredoc в shell. Сохраняй
   стиль и форматирование окружающего кода и документации.
4. **Проверка.** Минимум:
   ```bash
   pnpm install --frozen-lockfile   # если менялись зависимости
   pnpm run lint:docs               # Markdown
   ```
   Для пакетов, где есть скрипты, — `pnpm --filter <pkg> test` / `build`.
5. **Git.** Conventional Commits: `chore:`, `ci:`, `docs:`, `feat:`, `fix:`.
   Пуш в `main` — только если задача это предполагает.
6. **CI.** После пуша дождись результата:
   ```bash
   gh run list --repo iilmchat/ai-skillwharf --limit 1
   gh run watch <id> --repo iilmchat/ai-skillwharf --exit-status
   ```
7. **Отчёт.** Файлы, коммиты, команды проверки и их результат, ссылка на CI,
   оставшиеся риски.

## 4. Формат отчёта

| Шаг | Результат |
|---|---|
| Изменено | файлы/директории |
| Коммит | `hash` — сообщение |
| Проверка | команда → результат |
| CI | ссылка на run, conclusion |
| Риски / дальше | 1–3 пункта |

Если что-то заблокировано (права, токен, неясное решение) — остановись и
задай конкретный вопрос. Не обходи ограничения молча.

## 5. Технические заметки

- **Windows/git.** Файлы хранятся с LF; предупреждение `LF will be replaced
  by CRLF` при `git add` — нормальное, не «исправляй» его пересохранением.
- **pnpm.** `-w` — для корня воркспейса. После `pnpm add` всегда коммить
  `pnpm-lock.yaml`, иначе CI упадёт на `--frozen-lockfile`.
- **Docker.** На хосте Docker Desktop; перед docker-командами проверяй
  `docker info`, чужие контейнеры не останавливай.
- **Документация.** `docs/**` — источник правды по архитектуре. Структуру
  разделов не удалять; правки оформления допустимы, содержание — по задаче.
- **GitHub.** `gh` авторизован под `iilmchat`. Если push просит токен — не
  подставляй произвольный, сообщи и запроси инструкции.
