# ADR 0004: MCP-Коннекторы и Runtime-Безопасность (Agent Gateway)

**Статус:** Утверждено
**Дата:** 2026-11-13
**Контекст:** Рынок 2026 года требует управляемой автономии. 89% предприятий используют MCP. Модель больше не считается границей безопасности (defense-in-depth).

## 1. Контекст

Сейчас наши навыки (Skills) для Ozon и WB используют прямые вызовы (Mock). Это не масштабируется. Кроме того, Prompt Injection может заставить агента выполнить вредоносный код или отправить данные на сторонний сервер.

## 2. Решение

1. **MCP как стандарт:** В спецификацию `SKILL.md` добавляется поле `mcp_endpoint`. Навыки могут быть «обертками» над внешними MCP-серверами.
2. **Agent/MCP Gateway:** Создается отдельный слой (runtime-контроль), который перехватывает все вызовы инструментов (Tools) и проверяет аргументы на соответствие политикам (policy-as-code) до их исполнения в песочнице.
3. **FQDN-aware Egress:** В `SKILL.md` добавляется поле `egress_allowlist` (список доменов, к которым разрешено обращаться). Песочница блокирует любой сетевой трафик за пределами этого списка.

## 3. Последствия

* **Плюсы:** Защита от эксфильтрации данных. Возможность подключать тысячи готовых MCP-серверов.
* **Минусы:** Усложнение логики Gateway (дополнительная проверка каждого вызова).
