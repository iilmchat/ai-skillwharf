# Спецификация: Контроль затрат на LLM (Cost Guardrails)

**Статус:** Утверждено
**Дата:** 2026-11-13

## 1. Проблема

Без контроля затрат один пользователь может выжечь весь бюджет на API-ключи
LLM провайдера (например, GigaChat или OpenAI).

## 2. Решение

1. **Тарификация токенов:**
   - Каждый ответ LLM возвращает `usage.prompt_tokens` и
     `usage.completion_tokens`.
   - Стоимость рассчитывается по формуле:
     `(prompt_tokens + completion_tokens) * ЦЕНА_ЗА_1000_ТОКЕНОВ / 1000`.
   - Списание происходит через `BillingService.chargeForSkill` с типом
     `llm_usage`.

2. **Минимальный баланс:**
   - Для запуска графа агента пользователь должен иметь на балансе минимум
     0.50 ₽. Если меньше — агент не запускается (ошибка
     `errors.insufficient_funds`).

3. **Защита Admin Top-Up:**
   - Ручное пополнение баланса (`POST /billing/topup`) доступно только
     администраторам.
   - Обычные пользователи пополняют баланс только через ЮKassa
     (`POST /billing/create-payment`).

4. **Дневные лимиты токенов (Budget Guard):**
   - Жёсткий лимит — `User.dailyTokenLimit` (по умолчанию 100 000 токенов в
     сутки). Счётчик `dailyTokensUsed` сбрасывается лениво при первом запросе
     нового дня (граница — UTC).
   - **Reserve-before-call:** до обращения к провайдеру счётчик атомарно
     резервируется на оценку `prompt_tokens + output-резерв`
     (`LLM_RESERVE_OUTPUT_TOKENS`, по умолчанию 4096). `User.updateMany` с
     условием `dailyTokensUsed <= dailyTokenLimit - reserved` гарантирует, что
     параллельные вызовы не превысят лимит; если места нет — `429` в едином
     JSON-формате (`code = errors.daily_token_limit`) **до** вызова модели и до
     первой дельты стрима.
   - **Reconcile после ответа:** `actual = usage.total_tokens` (при отсутствии
     usage — оценка, см. п.5); `delta = actual - reserved`. Отрицательная
     разница возвращается атомарным decrement, положительная — добавляется с
     проверкой лимита; если actual не помещается, счётчик клампится к лимиту
     (жёсткий лимит не превышается) и пишется `gen_ai.budget.reconcile_overflow`.
     При ошибке провайдера до получения usage резерв откатывается.
   - Мягкий лимит — 80% от жёсткого (`DAILY_TOKEN_SOFT_LIMIT_RATIO`):
     превышение только пишется в лог событием `gen_ai.budget.soft_limit` и не
     блокирует вызов.
   - **Оценка без usage:** если провайдер (GigaChat) не прислал `usage`,
     расход оценивается токенизатором `cl100k_base` (js-tiktoken) с
     эвристическим fallback; событие `gen_ai.usage.fallback` и флаг
     `gen_ai.usage_estimated` в логе. Так как GigaChat тарифицирует input и
     output одинаково, для стоимости важен суммарный объём.
   - Ограничения приближения и раннего abort стрима — см.
     `docs/KNOWN_ISSUES.md`, KI-031 и KI-032.
