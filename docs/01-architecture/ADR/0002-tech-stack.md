# ADR 0002: Выбор технологического стека

**Статус:** Принято
**Дата:** 2026-11-12
**Контекст:** Проектирование ядра SkillWharf.

## 1. Контекст

Для реализации платформы SkillWharf (Hub-and-Spoke, автономные агенты, сложный биллинг) необходимо выбрать стек, который обеспечит высокую скорость разработки, строгую типизацию, безопасность и возможность горизонтального масштабирования.

## 2. Решение и обоснование по слоям

### Базовый слой

* **TypeScript + Node.js (LTS):** Единый язык для фронтенда и бэкенда. Позволяет использовать общие пакеты (`packages/shared`) для схем валидации (Zod) и типов.
* **pnpm workspaces:** Быстрый и надежный менеджер пакетов для монорепозитория, жестко контролирующий зависимости.

### Gateway и API

* **Fastify + NestJS:** NestJS дает предсказуемую модульную архитектуру (DI, модули), а Fastify обеспечивает высокую производительность HTTP и WebSocket (через Socket.IO).
* **WebSocket (Socket.IO) + OpenAI-совместимый HTTP API:** Стандартные протоколы для интеграции с мессенджерами и веб-клиентами.

### Агентный рантайм

* **LangGraph (TypeScript):** Альтернатива — написание собственного фреймворка (отклонено из-за сложности) или OpenAI Agents SDK (не дает нужной гибкости для аудита каждого шага). LangGraph позволяет строить графы состояний агента, где каждый узел — это отдельный аудируемый шаг, что критично для биллинга и отладки.

### Песочница (Sandbox Provider)

* **Основной бэкенд: Firecracker (microVM):** Обеспечивает аппаратную изоляцию (KVM), быструю загрузку (~125 мс) и минимальное потребление памяти. Это критически важно для безопасного выполнения сторонних Plugin'ов.
* **Fallback: gVisor:** Используется в облачных K8s-средах, где нет доступа к `/dev/kvm`, но требуется строгая изоляция (RuntimeClass).

### Память и векторный поиск

* **MVP: pgvector (PostgreSQL):** Позволяет хранить конфигурацию, биллинг и эмбеддинги в одной БД, упрощая инфраструктуру на старте.
* **Рост: Qdrant:** Выделенная векторная БД с открытым исходным кодом для масштабирования RAG, если pgvector перестанет справляться.

### Биллинг

* **Платёжный шлюз: ЮKassa (основной):** Поддерживает marketplace splits (для Revenue Share 85/15) и соответствует требованиям РФ.
* **Ledger: PostgreSQL (append-only):** Гарантирует транзакционную целостность и защиту от подделки истории транзакций.

## 3. Последствия

* **Положительные:** Единый язык (TS) снижает когнитивную нагрузку. Строгая изоляция через Firecracker защищает от RCE в сторонних плагинах.
* **Отрицательные:** Монорепозиторий и LangGraph требуют высокой квалификации разработчиков. Firecracker требует bare-metal серверов или KVM-инстансов.
