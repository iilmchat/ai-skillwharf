# Product & Engineering Roadmap V2 — SkillWharf (Post-GA)

**Базовая точка:** релиз `v1.0.0-ga` (Этапы 0–3, Спринты 1–28 завершены и
зафиксированы в [ROADMAP.md](ROADMAP.md)).

**Планируемые версии:** `v1.1.0` → `v1.2.0` → `v1.3.0` → `v2.0.0`
(Спринты 29–36).

**Методология:** Stage-Gate (релизы) -> Sprints (2-недельные итерации) ->
Atomic Tasks. Документ не заменяет [ROADMAP.md](ROADMAP.md), а продолжает его:
завершённые этапы остаются в первом файле как аудиторский след.

**Правило для AI-агентов (обязательно):**

1. При завершении задачи меняй `[ ]` на `[x]` и указывай ID коммита/PR в
   «Журнале выполнения и блокеров (Спринты 29+)».
2. Если задача заблокирована или найден баг — ставь `[!]` и заноси запись в
   журнал с присвоением `KI-XXX` в [KNOWN_ISSUES.md](../KNOWN_ISSUES.md).
3. Не удаляй закрытые спринты и этапы — они служат аудиторским следом.
4. Не открывай новые KI с номерами ниже `KI-088` — диапазон до `KI-087`
   занят базовой дорожной картой.

## Этап 4: Агентная надёжность, Evals и Наблюдаемость (`v1.1.0`)

**Цель этапа:** сделать качество агентов измеримым и управляемым: автоматические
оценки до промоушена промптов, многоагентная оркестрация со сквозной
трассировкой и семантическим кешем для снижения latency и стоимости LLM.

### Sprint 29 — Automated LLM Evals & Regression Datasets

* [x] **[EVAL-29.1]** Золотые датасеты (Golden Datasets) для всех 12 треков
  `A–L`: репрезентативные задачи, эталонные ответы и метрики качества
  (correctness, tool selection, HITL-поведение) с версионированием в git.
  Созданы `evals/datasets/track-a.json` … `track-l.json` (36 кейсов) и реестр
  `index.json`; валидатор `scripts/run-evals.mjs` и npm-скрипт
  `pnpm evals:validate` добавлены в CI. Методика — `docs/development/LLM-Evals-Guide.md`.
* [x] **[EVAL-29.2]** LLM-as-a-Judge: оценка ответов агентов второй моделью по
  калиброванным рубрикам, с хранением вердикта и обоснования в БД (бэкенд —
  см. журнал ниже).
* [x] **[EVAL-29.3]** Гейт перед промоушеном победителя A/B-эксперимента
  промптов: без прохода порога качества версия B не повышается (интеграция с
  `PromptExperiment` Sprint 28); CI-прогон — отдельная задача.
* [x] **[EVAL-29.4]** Дашборд регрессий в Grafana: pass rate и средний балл
  LLM-as-a-Judge по промптам/трекам, hit rate и сэкономленные токены
  семантического кеша, мультиагентные handoffs (`evals-and-cache.json`).
  Алерты на критичные деградации — отдельная задача.
* [x] **[WEB-29.5]** UI-панель запуска и просмотра LLM Evals в Control Plane
  (версия, фильтр по треку A–L, история прогонов и детализация кейсов) +
  локализованная обработка `errors.eval_gate_failed` при промоушене версии B
  (UI-часть **EVAL-29.3**; без коммита, изменения в рабочем дереве).

### Sprint 30 — Multi-Agent Orchestration & Semantic Cache

* [x] **[GRAPH-30.1]** Графы LangGraph «Супервизор -> Специализированные
  воркеры»: динамическая маршрутизация задач по трекам `A–L` и делегирование
  инструментов с сохранением checkpoint'ов (бэкенд — см. журнал ниже).
* [ ] **[GRAPH-30.2]** Сквозной `trace_id` через API, `llm-worker`, воркеры и
  Tempo: один trace на всю цепочку multi-agent с корреляцией в JSON-логах.
* [x] **[CACHE-30.1]** Семантическое кеширование типовых LLM-запросов в
  Redis по близости эмбеддингов, с hit/miss-метриками и экономией токенов
  (бэкенд — см. журнал ниже).
* [x] **[CACHE-30.2]** Политика инвалидации и TTL кеша при смене системного
  промпта или версии модели; принудительный bypass для вызовов с инструментами
  (Redis `EX`, ключ из `userId`/`promptVersionId`/`model`).
* [x] **[WEB-30.3]** UI мультиагентных handoff'ов и семантического кеша:
  подсветка перехода `fromRole → toRole` на карточках AI-Офиса, лента последних
  передач с причиной, бейдж «Из кеша · 0 ₽» с tooltip в ленте чата; валидация
  `office_event` и метаданных ответа через Zod, RU/EN и unit-тесты (без коммита,
  изменения в рабочем дереве).

## Этап 5: Масштабируемый Multi-Tenancy и Корпоративные Коннекторы (`v1.2.0`)

**Цель этапа:** подготовить платформу к нескольким организациям на одном
инстансе и подключить 1С как корпоративный источник данных для треков H, J, K, L.

### Sprint 31 — Organizations, Workspaces & Granular RBAC

* [x] **[ORG-31.1]** Иерархия `Organization -> Workspace -> Members`: модели,
  миграции и API управления membership с приглашениями (бэкенд — см. журнал).
* [x] **[ORG-31.2]** Детальная матрица прав: RBAC на ресурсы + ABAC на лимиты
  HITL (кто может одобрять, лимиты сумм и дневные бюджеты).
* [x] **[ORG-31.3]** Per-user/per-workspace привязка установленных навыков
  (`InstalledSkill.userId`/`workspaceId`) — полное закрытие **KI-086**.
* [x] **[WEB-31.4]** UI воркспейсов: переключатель активного воркспейса с
  ролью в шапке/сайдбаре, заголовок `X-Workspace-Id` во всех запросах и
  инвалидация кэшей при смене; страница «Команда и доступ» с таблицей
  участников, ролями `owner/admin/operator/viewer`, лимитом HITL и формами
  добавления/обновления (UI-часть **ORG-31.1/ORG-31.2**; без коммита, изменения
  в рабочем дереве).

### Sprint 32 — Native 1C:Enterprise / 1C:Fresh & Event-Driven Webhooks

* [x] **[CONNECT-32.1]** Официальный MCP-коннектор для 1С (OData и
  HTTP-сервисы) для треков **H** (документооборот), **J** (склад/учёт),
  **K** (опт) и **L** (производство), с live-проверками как у Битрикс24 и
  МойСклад. Реализован `infra/mcp/1c/server.mjs` с OData-инструментами,
  per-request кредами, retry и тестами; HTTP-сервисы 1С — остаток.
* [x] **[CONNECT-32.2]** Входящие webhook-триггеры (Event-Driven Agents):
  CRUD `/triggers` с привязкой к воркспейсу, публичный приём по
  `X-Trigger-Secret` (constant-time), подстановка payload в промпт и запуск
  автономного диалога (бэкенд — см. журнал ниже).
* [x] **[WEB-32.3]** UI: карточка «1С:Предприятие (OData)» в «Интеграциях»
  (OData URL + логин + пароль через `SecretField`, Zod-валидация, RU/EN) и
  секция «Вебхук-триггеры» на `/app/settings`: форма создания (название,
  источник, шаблон промпта), карточка с Webhook URL
  `/api/v1/webhooks/triggers/:slug` и секретом `X-Trigger-Secret`
  (маскировка, копирование), список со счётчиком срабатываний и удалением;
  Zod-клиент `/api/v1/triggers`, unit-тесты (без коммита, изменения в
  рабочем дереве).

* [x] **[OUTBOX-33.2]** Системный кошелёк платформы (platform treasury) с
  реальным credit комиссии `platform_fee` вместо информационной проводки.
* [ ] **[OUTBOX-33.3]** Периодическая сверка биллинга: Ledger ↔
  Journal ЮKassa, отчёт по расхождениям и алерт при рассинхроне.

### Sprint 34 — Cloud KMS / HashiCorp Vault & High Availability

* [ ] **[KMS-34.1]** Адаптер Yandex Cloud KMS для `KeyManagementService`.
* [ ] **[KMS-34.2]** Адаптер HashiCorp Vault для `KeyManagementService` —

* [ ] **[HA-34.1]** Нагрузочное тестирование горизонтального масштабирования:

  Ledger, метрики latency/p95 под нагрузкой.
