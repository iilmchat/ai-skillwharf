# Product & Engineering Roadmap V2 — SkillWharf (Post-GA)

**Базовая точка:** релиз `v1.0.0-ga` (Этапы 0–3, Спринты 1–28 завершены и
зафиксированы в [ROADMAP.md](ROADMAP.md)).

**Планируемые версии:** `v1.1.0` → `v1.2.0` → `v1.3.0` → `v2.0.0`
(Спринты 29–36).

**Методология:** Stage-Gate (релизы) -> Sprints (2-недельные итерации) ->
Atomic Tasks. Документ не заменяет [ROADMAP.md](ROADMAP.md), а продолжает его:
завершённые этапы остаются в первом файле как аудиторский след.

**Правило для AI-агентов (обязательно):**

1. При завершении задачи меняй `[ ]` на `[x]` и указывай ID коммита/PR в
   «Журнале выполнения и блокеров (Спринты 29+)».
2. Если задача заблокирована или найден баг — ставь `[!]` и заноси запись в
   журнал с присвоением `KI-XXX` в [KNOWN_ISSUES.md](../KNOWN_ISSUES.md).
3. Не удаляй закрытые спринты и этапы — они служат аудиторским следом.
4. Не открывай новые KI с номерами ниже `KI-088` — диапазон до `KI-087`
   занят базовой дорожной картой.

## Этап 4: Агентная надёжность, Evals и Наблюдаемость (`v1.1.0`)

**Цель этапа:** сделать качество агентов измеримым и управляемым: автоматические
оценки до промоушена промптов, многоагентная оркестрация со сквозной
трассировкой и семантическим кешем для снижения latency и стоимости LLM.

### Sprint 29 — Automated LLM Evals & Regression Datasets

* [ ] **[EVAL-29.1]** Золотые датасеты (Golden Datasets) для всех 12 треков
  `A–L`: репрезентативные задачи, эталонные ответы и метрики качества
  (correctness, tool selection, HITL-поведение) с версионированием в git.
* [ ] **[EVAL-29.2]** LLM-as-a-Judge: оценка ответов агентов второй моделью по
  калиброванным рубрикам, с хранением вердикта и обоснования в БД.
* [ ] **[EVAL-29.3]** Автоматический прогон Evals в CI и перед промоушеном
  победителя A/B-эксперимента промптов: без прохода порога качества версия B
  не повышается (интеграция с `PromptExperiment` Sprint 28).
* [ ] **[EVAL-29.4]** Дашборд регрессий и алерты в Grafana: динамика quality
  score по трекам, критичные деградации и ссылки на конкретные eval-случаи.

### Sprint 30 — Multi-Agent Orchestration & Semantic Cache

* [ ] **[GRAPH-30.1]** Графы LangGraph «Супервизор -> Специализированные
  воркеры»: динамическая маршрутизация задач по трекам `A–L` и делегирование
  инструментов с сохранением checkpoint'ов.
* [ ] **[GRAPH-30.2]** Сквозной `trace_id` через API, `llm-worker`, воркеры и
  Tempo: один trace на всю цепочку_multi-agent с корреляцией в JSON-логах.
* [ ] **[CACHE-30.1]** Семантическое кеширование типовых LLM-запросов в
  Redis/Qdrant по близости эмбеддингов, с hit-rate и экономией токенов в
  метриках.
* [ ] **[CACHE-30.2]** Политика инвалидации и TTL кеша при смене системного
  промпта или версии модели; принудительный bypass для HITL и биллинговых
  вызовов.

## Этап 5: Масштабируемый Multi-Tenancy и Корпоративные Коннекторы (`v1.2.0`)

**Цель этапа:** подготовить платформу к нескольким организациям на одном
инстансе и подключить 1С как корпоративный источник данных для треков H, J, K, L.

### Sprint 31 — Organizations, Workspaces & Granular RBAC

* [ ] **[ORG-31.1]** Иерархия `Organization -> Workspace -> Members`: модели,
  миграции и API управления membership с приглашениями.
* [ ] **[ORG-31.2]** Детальная матрица прав: RBAC на ресурсы + ABAC на лимиты
  HITL (кто может одобрять, лимиты сумм и дневные бюджеты).
* [ ] **[ORG-31.3]** Per-user привязка установленных навыков
  (`InstalledSkill.userId`) — закрытие остатка **KI-086** (флаг «Установлено»
  в витрине становится персональным).

### Sprint 32 — Native 1C:Enterprise / 1C:Fresh & Event-Driven Webhooks

* [ ] **[CONNECT-32.1]** Официальный MCP-коннектор для 1С (OData и
  HTTP-сервисы) для треков **H** (документооборот), **J** (склад/учёт),
  **K** (опт) и **L** (производство), с live-проверками как у Битрикс24 и
  МойСклад.
* [ ] **[CONNECT-32.2]** Входящие webhook-триггеры от Битрикс24, МойСклад и
  Telegram (Event-Driven Agents): подписка, верификация подписи/idempotency и
  запуск агента по событию без опросов.

## Этап 6: Финансовый клиринг и Распределённая отказоустойчивость (`v1.3.0`)

**Цель этапа:** гарантировать доставку выплат и секретов даже при сбоях, а также
подтвердить горизонтальное масштабирование API и `llm-worker`.

### Sprint 33 — Transactional Outbox & Platform Treasury

* [ ] **[OUTBOX-33.1]** Паттерн Transactional Outbox (`BillingOutbox` + BullMQ)
  для гарантированной доставки выплат Revenue Share 85/15 в ЮKassa — закрытие
  **KI-087** (перевод больше не теряется при недоступности провайдера).
* [ ] **[OUTBOX-33.2]** Системный кошелёк платформы (platform treasury) с
  реальным credit комиссии `platform_fee` вместо информационной проводки.
* [ ] **[OUTBOX-33.3]** Периодическая сверка биллинга: Ledger ↔
  Journal ЮKassa, отчёт по расхождениям и алерт при рассинхроне.

### Sprint 34 — Cloud KMS / HashiCorp Vault & High Availability

* [ ] **[KMS-34.1]** Адаптер Yandex Cloud KMS для `KeyManagementService`.
* [ ] **[KMS-34.2]** Адаптер HashiCorp Vault для `KeyManagementService` —
  закрытие остатка **KI-053**; unit- и smoke-тесты ротации ключей.
* [ ] **[HA-34.1]** Нагрузочное тестирование горизонтального масштабирования:
  `3+` реплик API и `llm-worker`, проверка idempotency и отсутствия гонок в
  Ledger, метрики latency/p95 под нагрузкой.

## Этап 7: Расширение экосистемы и No-Code конструктор (`v2.0.0`)

**Цель этапа:** перейти от ручной настройки агентов к визуальному конструированию
и безопасной публикации навыков сторонними авторами.

### Sprint 35 — Visual No-Code Agent & Skill Builder

* [ ] **[BUILDER-35.1]** Визуальный конструктор ролей в UI: переименование и
  настройка «столов» AI-Офиса под конкретного заказчика.
* [ ] **[BUILDER-35.2]** Сборка агента из навыков Marketplace в 1 клик
  (drag-and-drop), с предпросмотром инструментов и разрешений.
* [ ] **[BUILDER-35.3]** Настройка регламента HITL и дневного бюджета агента
  прямо в конструкторе, с валидацией и сохранением в конфигурацию workspace.

### Sprint 36 — Developer Portal & Automated Security Audit

* [ ] **[DEVPORTAL-36.1]** Личный кабинет автора навыков: статистика
  установок, версии манифеста, управление ключами подписи Ed25519.
* [ ] **[DEVPORTAL-36.2]** Автоматический статический и песочный аудит перед
  публикацией в `/app/marketplace`: проверка манифеста, seccomp,
  egress-политики и подписи; блокировка публикации при findings.
* [ ] **[DEVPORTAL-36.3]** Вывод вознаграждений автору (Revenue Share 85/15):
  история начислений, статус переводов и выгрузка отчёта.
