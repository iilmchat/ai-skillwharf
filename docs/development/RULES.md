# Правила разработки SkillWharf

## 1. Код (TypeScript)

1.1. Строгая типизация. `any` запрещен.
1.2. Использовать Zod для валидации всех внешних данных.
1.3. DI (Dependency Injection) в NestJS только через конструктор.
1.4. Ошибки API возвращать в едином формате JSON.

## 2. Архитектура

2.1. Ядро Gateway управляет сессиями, но не выполняет код плагинов напрямую.
2.2. Выполнение любого стороннего кода — только в Sandbox.
2.3. Все финансовые операции (Billing) проходят через BAL.
2.4. Все действия (запуск Tools, списание средств) пишутся в Append-only Ledger.

## 3. Git и процесс

3.1. Коммиты: `<type>(<scope>): <subject>` (Conventional Commits).
3.2. DSH (DeepSeek Harness/Агенты) не делают `git add -A` и не коммитят без явного разрешения.
3.3. Документация (`docs/`) обновляется в том же коммите, что и код.
3.4. Перед пушем локально прогнать: `pnpm lint`, `pnpm test`, `pnpm build:api`.

## 4. Документация

4.1. Любая проблема фиксируется в `docs/KNOWN_ISSUES.md`.
4.2. Крупные архитектурные решения фиксируются в `docs/architecture/ADR/`.
